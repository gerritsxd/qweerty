Predicting Parliamentary Votes from Debate Speeches

Can we predict how a Dutch MP will vote based on what they say in debate?

Tweede Kamer Open Data — Team Project — February 2026

The Research Question

The Dutch parliament publishes full debate transcripts and individual votes.

  • If speech predicts votes → MPs reveal intent through language; debate is substantive
  • If not → Voting is purely party-line; deliberation doesn't matter

Data: 153,000 speech–vote pairs from the Tweede Kamer Open Data API

Data Pipeline — Overview

OData API → Stemming, Besluit, Agendapunt, Activiteit
Verslag XML → Parse speeches (speaker, party, text)
LINK by date → speech_vote_pairs.parquet
Temporal split → Train ≤2021 Val 2022 Test ≥2023

We test on future votes the model has never seen.

Database Model — Entity Relationships

Core tables used for speech-to-vote linking (arrows = foreign keys):

Vergadering → Verslag (transcript XML)
Activiteit → Agendapunt → Besluit → Stemming
Persoon ↔ Fractie (via FractieZetelPersoon)
Zaak → kabinetsappreciatie, zaak_soort (matched by text overlap)

Linking logic: Speech from Verslag XML (speaker + date) → find Stemming on same date where ActorFractie = speaker's party (or Persoon_Id for roll-call votes).

What Data Does Each Model Use?

ModelInput columnsSource
Baseline fractie speech_vote_pairs (from Verslag XML spreker)
Structural (XGBoost) fractie, topic_cluster, zaak_soort, kabinetsappreciatie, is_coalition, speaker_loyalty, party_domain_voor_rate, party_recent_voor_rate, speaker_topic_loyalty speech_vote_pairs + Zaak (token match) + train-derived stats
RobBERT fractie, besluit_tekst, agendapunt_onderwerp, speech_text speech_vote_pairs (Besluit + Agendapunt context from link)
Ensemble proba_struct, proba_robbert, agree, conf_delta, is_coalition, party_domain_voor_rate, topic_cluster Outputs of Structural + RobBERT + meta-features

Derived from

  • topic_cluster — TF-IDF + KMeans on besluit_tekst + agendapunt_onderwerp (20 clusters)
  • kabinetsappreciatie, zaak_soort — matched from Zaak by token overlap with agendapunt_onderwerp
  • is_coalition — hardcoded by year (e.g. 2024: PVV, VVD, NSC, BBB)
  • speaker_loyalty, party_*_rate — computed from training data only (no leakage)

RobBERT v2 — The Transformer Model

Base model: DTAI-KULeuven/robbert-2023-dutch-base — Dutch RoBERTa from KU Leuven (~125M parameters), pre-trained on Dutch text.

Input format

Concatenated text with </s> separator:

[party]  [besluit_tekst]  [topic]  [speech]

Truncation: besluit 500 chars, topic 300 chars, speech 3000 chars. Party and context go first so they're never cut off.

Architecture

RobBERT encoder (12 layers) → CLS token (768-dim) → MLP classifier: 768 → 256 (GELU, Dropout) → 64 (GELU, Dropout) → 2 (Voor/Tegen).

Training innovations

  • Focal loss — focuses on hard-to-classify examples; confident correct predictions get low loss
  • Progressive unfreezing — start with classifier only; gradually unfreeze encoder layers (0 → 2 → 4 → 6 layers)
  • Encoder detaching — when encoder is frozen, skip backward pass through it (6× speedup)
  • Sample reweighting — per epoch, upweight samples the model gets wrong or is uncertain about
  • Early stopping — patience 4 epochs; return best model, not final epoch

Best checkpoint: Epoch 3 (74.0% val accuracy, 2 encoder layers unfrozen).

Structural Model — XGBoost

Purpose: Predict vote from structured metadata only — no speech text. Captures party patterns, coalition dynamics, and historical voting rates.

Features (no text)

  • fractie — party one-hot (VVD, CDA, PVV, etc.)
  • topic_cluster — 20 policy domains from TF-IDF + KMeans on besluit + agendapunt text
  • zaak_soort — Motie, Amendement, etc.
  • kabinetsappreciatie — government position (Ontraden, Overgenomen, etc.)
  • is_coalition — 0/1, whether party is in government that year
  • speaker_loyalty — how often this MP votes with party majority (from train)
  • party_domain_voor_rate — % Voor by this party in this topic cluster
  • party_recent_voor_rate — party's overall Voor rate
  • speaker_topic_loyalty — does this speaker follow party line on this topic?

Classifier

XGBoost: 500 trees, max_depth 6, class_weight balanced.

Result: 53.3% test accuracy — underperforms baseline. Suggests temporal distribution shift: patterns from 2013–2021 don't generalize to 2023+. But its probabilities still help the ensemble.

Ensemble — Combining Both

The stacked ensemble uses a meta-learner (Logistic Regression) to combine:

  • proba_struct — XGBoost's Voor probability
  • proba_robbert — RobBERT's Voor probability
  • agree — 1 if both predict same class
  • conf_delta — |proba_struct − proba_robbert|
  • Optional: is_coalition, party_domain_voor_rate, topic_cluster

Meta-learner learns when to trust RobBERT vs. structural model. 71.9% test accuracy — best of all models.

Key Findings

  1. Speech text adds real predictive value (+9.3pp over party alone) — MPs reveal intent through language
  2. Ensemble captures complementary signals — structural + transformer
  3. Party discipline varies dramatically — VVD/NSC/CDA predictable; PVV/FVD near-random
  4. Confident predictions are reliable — 95.8% accuracy when model confidence > 80%

Limitations & Next Steps

Limitations:

  • 57% of predictions are low-confidence (<0.6)
  • Populist parties (~51%) near-random
  • Structural model underperforms on test (53.3%) — temporal distribution shift

Next steps:

  • Retrain RobBERT with bug fix (return best model, not final epoch)
  • Per-party or per-topic specialized models
  • Rebellion detection: predict when MP votes against party
  • SHAP analysis for interpretability
