How It Works

From API request to individual vote prediction — a comprehensive guide to our pipeline

1. Data Sources — The Tweede Kamer Open Data

We use the OData v4 API (a REST-based protocol for querying structured data) at gegevensmagazijn.tweedekamer.nl. The parliament publishes 35+ entity types: people, parties, agenda items, decisions, votes, and more.

Pagination (how we fetch large datasets): The API returns ~250 records per page. We follow @odata.nextLink until all records are retrieved. We filter with Verwijderd eq false to exclude deleted records.

Two data streams: (1) Structured tables are fetched as JSON and preprocessed into Parquet (columnar, compressed). (2) Debate transcripts are downloaded as XML from Verslag/{Id}/resource and parsed separately.

OData API → data/raw/*.json → data/processed/*.parquet + Verslag XML → speeches.parquet
2. Parsing Debate Transcripts

The XML transcripts follow a hierarchical structure. We traverse: vergadering (meeting) → activiteit (activity) → activiteithoofd (agenda head) → activiteitdeel (segment) → woordvoerder (speaker).

Per speech we extract: speaker name, party (fractie), speech text, timestamps, activity IDs. Interruptions are stored as separate records.

Verslag status priority: When multiple transcript versions exist, we prefer Gecorrigeerd (corrected) > Ongecorrigeerd > Voorpublicatie > Casco (skeleton only).

Text cleaning: We remove attribution lines (e.g. "Mevrouw X (VVD):") and join paragraphs into clean speech text.

vergadering
└─ activiteit (activiteit_id, onderwerp)
└─ activiteithoofd

└─ woordvoerder (spreker, fractie, tekst)
3. Linking Speeches to Votes — The Hardest Step

The core problem: Transcripts come from Vlos; votes from Parlis/Sesam. These systems use different ID spaces — zero overlap. We must link by matching context.

Strategy 1 — Direct match: When the transcript references an activiteit_id, we follow the chain: Activiteit → Agendapunt → Besluit → Stemming. We filter substantive speeches (not chair, not interruption, has party, >50 chars).

Strategy 2 — Date + topic fallback: When no direct link exists, we find "Stemmingen" activities on the same date (or +1 day). We require ≥2 shared words between speech topic and agenda item (after stopword removal).

Vote lookup: For each Besluit, we find the speaker's vote by: (1) individual match on Persoon_Id, (2) faction match on ActorFractie, (3) lowercase fuzzy faction fallback.

Deduplication: If an MP spoke multiple times on the same decision, we keep the longest speech. Link quality: 1 = direct, 3 = topic-filtered date.

PersonMatcher: To map speech speakers to canonical Persoon.Id, we use 4 strategies: exact (name, party), party aliases (e.g. "GroenLinks" → "GL"), compound name prefix ("Dik" → "Dik-Faber"), and unambiguous name-only. 99.3% coverage, 16 unmatched pairs.

Speech → Agendapunt → Besluit → Stemming

Result: 153,000 speech–vote pairs.

4. Temporal Split — Why We Separate Past from Future

A temporal split ensures the model never sees the future: we train on past data, validate on a held-out year, and test on future years. This prevents data leakage and simulates real-world deployment (predicting votes before they happen).

Train ≤2021 (92,919) Val 2022 (12,414) Test ≥2023 (48,021)

Class distribution: ~60% Voor, ~40% Tegen. The model must learn to predict the minority class (Tegen) despite imbalance.

5. Feature Engineering — What the Model Sees

Basic features

speech_length (character count), optional stance keywords.

Zaak matching

Token overlap between agendapunt_onderwerp and Zaak records to find kabinetsappreciatie (government position: Ontraden, Overgenomen, etc.) and zaak_soort (Motie, Amendement). Requires ≥2 shared words.

Coalition detection

Cabinet period lookup (Rutte II/III/IV, Schoof) with party lists. is_coalition = 1 if the MP's party was in government on the vote date.

Topic clustering

TF-IDF on besluit_tekst + agendapunt_onderwerp, KMeans into 20 clusters. Each vote gets a topic_cluster so we learn "how does party X vote on immigration?" not just "how does party X vote?"

Historical rates (training data only — no leakage)

party_domain_voor_rate: % Voor by this party in this topic cluster. party_recent_voor_rate: party's overall Voor rate. speaker_topic_loyalty: does this MP break from party majority on this topic?

Speaker loyalty

How often does this MP vote with their party majority? Computed from training data.

6. The Models — From Baseline to Ensemble

Baseline (60.7% test accuracy)

Predict the majority vote per party — "how would most VVD members vote?" No speech text. Establishes how much party alone explains votes.

Structural model (53.3% test)

XGBoost with 500 trees on all structured features (party, coalition, topic cluster, historical rates, speaker loyalty). Underperforms on test due to temporal distribution shift — political patterns change over time.

RobBERT v2 (70.0% test)

RobBERT is Dutch RoBERTa (125M parameters), pre-trained on billions of Dutch words. We fine-tune it to read speech text and output Voor/Tegen probability.

Input: [party] </s> [besluit_tekst] </s> [topic] </s> [speech]. Truncation: besluit 300 chars, topic 200, speech 1500. Tokenized to 256 tokens.

Classifier head: 768 → 256 → 64 → 2 (GELU activation, 30% dropout).

Focal loss (gamma=2.0): downweights easy examples, focuses on hard ones — the model cares more about mistakes.

Progressive unfreezing: Epoch 0: classifier only. Epoch 3: top 2 encoder layers. Epoch 6: top 4. Gradually adapts language understanding.

Sample reweighting: mastered (correct + high conf) = 0.3×, uncertain = 1.5×, wrong = 2.0×. Focuses training on what the model struggles with.

Input text (256 tokens) → RobBERT encoder (768-dim) → CLS token → Linear(768→256) → GELU → Dropout → Linear(256→64) → GELU → Dropout → Linear(64→2) → Softmax → [P(Voor), P(Tegen)]

Ensemble (71.9% test)

Logistic regression meta-learner on: structural probability, RobBERT probability, agreement (do they match?), confidence delta. Combines both models for best results.

7. Results — What the Model Gets Right (and Wrong)

Overall: 71.9% accuracy, 0.711 F1 (macro). Precision: Tegen 0.633, Voor 0.785. Recall: Tegen 0.691, Voor 0.738.

Coalition parties (VVD, NSC, CDA, CU) are highly predictable — party discipline and coalition agreements align rhetoric with votes. Populist opposition (PVV, FVD) are near-random — their voting is less correlated with speech content.

Confidence calibration: When the model is >80% confident, accuracy is 95.8%. When <60% confident, only 58.4%. Low-confidence predictions are less reliable.
